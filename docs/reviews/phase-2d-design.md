# Phase 2d — external change reconciliation design consult

## VERDICT

Phase 2d should put the native `notify` watcher and the debounce/stability/read/hash/project/validate engine in the Tauri-free core, while `src-tauri` owns one open-workspace lifecycle, the app-write revision ledger, an ordered/coalesced reconciliation queue, and a Tauri wake-up event; the frontend drains that queue through a command because an event is a hint and may be missed. The brief is wrong to describe the observable clean case as “no dirty draft”: this application can prove only that no write surface capable of targeting the document is open, and a pristine surface must therefore take the conflict path too. Automatic reload is not a confirmed adoption; it is a guarded `rereadDocument` installation using the existing per-document projection and global selection counters. A watcher-origin conflict is a distinct origin of the shared conflict model—there was no failed save—but it must still use `adoptDiskVersion` as the only confirmed-install door and `conflictChoicesFor` as the only choice-list producer. All five plan offers ship, but not as five new buttons: comparison is the always-visible read-only panel, and save-as-new is the existing staged manual-resolution recovery that preserves only supported logical fields. Cut the phase into eight dependency-ordered steps and require core/model tests, mounted tests, a reviewed temporary instrument, and a bilingual real-WKWebView reading with real filesystem writes and a command counter; without that last observation the sharpest green-suite failure is an incomplete open-surface registry silently auto-reloading over a live draft.

## Q1 — Where the watcher lives and what it is

**Ruling: the core owns a `notify`-backed native watcher plus the deterministic reconciliation engine, while `src-tauri` owns its open-workspace lifetime and event bridge; polling is a fallback for an unavailable native backend, not the primary mechanism.**

The plan itself puts `watch/` under `espansoconfig-core` and the Rust-to-frontend bridge in `src-tauri/events.rs` (`IMPLEMENTATION_PLAN.md:270-292`). That is compatible with the absolute dependency rule: the core is forbidden to depend on Tauri, not on a Tauri-independent filesystem crate (`CLAUDE.md:32-40`; `crates/espansoconfig-core/Cargo.toml:10-28`). Use the `notify` crate's recommended native watcher recursively on exactly `<root>/config` and `<root>/match`, and put a small periodic rescan behind the same core interface only when the native watcher reports an error or cannot be established. Do not poll continuously in the normal case, and do not use a Tauri filesystem plugin: it would move a testable domain pipeline into the window boundary for no gain.

The current `watch` module contains only `ContentRevision` and explicitly says the debounced watcher is later work (`crates/espansoconfig-core/src/watch/mod.rs:1-13`); its byte hash is already the right identity, including a distinct hash for a missing final newline (`crates/espansoconfig-core/src/watch/mod.rs:20-40`, `crates/espansoconfig-core/src/watch/mod.rs:125-145`). Extend that module with an injected-clock/injected-reader state machine. The native callback contributes only path hints. The core then owns plan steps 1–3 and 5: coalesce per path for 150–300 ms, require two equal successful reads separated by a short probe interval, hash the exact bytes, project through the same source-to-document path, and run the pure semantic report. `project_source` already parses exact source text without a workspace (`crates/espansoconfig-core/src/workspace/mod.rs:667-701`), and validation is already a pure `DocumentView -> Vec<Finding>` report rather than a filesystem gate (`crates/espansoconfig-core/src/validate/mod.rs:1-18`). A parse failure is therefore a stable observation with diagnostics, not an absent observation.

`src-tauri` owns the parts that are facts about this application session: mapping a path to the open `DocumentId`, comparing against the app-write ledger in step 4, assigning a monotonically increasing workspace epoch and observation sequence, queuing the typed result, and waking the window. The existing session holds at most one open workspace (`src-tauri/src/commands.rs:190-219`) and replaces it only after a successful discovery (`src-tauri/src/commands.rs:251-265`). On successful `open_workspace`, cancel and join the previous watcher, increment the epoch, install the new workspace, then start the new watch roots; on a failed open, keep both the previous workspace and its watcher. Dropping the application drops the watcher. An old callback carrying an earlier epoch is discarded before it can name a document. There is no separate close command today, so replacement and application shutdown are the two close events.

The watcher remains live during saves. Stopping it around a save would create the one interval in which an external writer can be missed; self-write suppression exists precisely so pausing is unnecessary. The core watcher and `Workspace::refresh` must share one observation/coalescing coordinator rather than race two cache installations. `Workspace::refresh` is already documented as the method a watcher drives and reparses only when the content hash changes (`crates/espansoconfig-core/src/workspace/mod.rs:508-530`). The command/session mutex already serializes cache-mutating commands (`crates/espansoconfig-core/src/workspace/mod.rs:330-341`; `src-tauri/src/commands.rs:729-765`). Debounce and stability waits occur outside that mutex; only the final install/sequence allocation is serialized.

Without any window, core tests can drive arbitrary hint storms, transient reads, equal consecutive reads, parse failures, semantic findings, add/remove/rename rescans, and self-hash equality through injected inputs. A real-filesystem `notify` integration belongs in `src-tauri`, because that is where open/replace/drop lifetime and native callback delivery meet. Added and removed YAML files must be separate typed observations rather than forced through the seven content steps: the plan already names document-added and document-removed events (`IMPLEMENTATION_PLAN.md:515-522`), while discovery deliberately walks only `config/` and `match/` (`crates/espansoconfig-core/src/discovery.rs:262-285`). A removal has no stable content to parse; an addition needs a rescan that preserves existing path-based `DocumentId`s, whose current identity table was built specifically so additions do not re-point surviving files (`crates/espansoconfig-core/src/workspace/mod.rs:201-209`, `crates/espansoconfig-core/src/workspace/mod.rs:360-387`).

## Q2 — Self-write suppression

**Ruling: suppress a stable observation only when its document and exact `ContentRevision` equal the latest committed revision recorded by `run_one_save` for that open-workspace epoch, retaining that ledger entry through duplicate hints until a different stable revision is observed.**

The record is `last_app_write[DocumentId] = { workspace_epoch, revision }`, stored beside the open Tauri session—not in global core state and not in the frontend. Set it only for `Ok(SavedDocument { committed: true, revision, .. })`, before handing the result to `after_a_save`. `SavedDocument::revision` is already specified as the post-rename read-back hash and expressly as “the hash its watcher must ignore” (`crates/espansoconfig-core/src/persist/save.rs:518-542`); `committed: false` means no rename happened and therefore must not mint an app-write record (`crates/espansoconfig-core/src/persist/save.rs:581-600`). Keep a matching entry long enough to absorb the several native notifications one atomic replacement may generate. Clear it when a different stabilized revision for that document is accepted, replace it on the next committed app save, and discard the whole map on workspace replacement.

This update belongs inside the shared tail. All six writers converge at `run_one_save`, which is explicitly the one command-layer cache-coherency policy (`src-tauri/src/commands.rs:951-1005`), and every success currently goes through `after_a_save` while a locked revision mismatch goes through `conflict_after_the_lock` (`src-tauri/src/commands.rs:1029-1044`). Do not add a second “remember my write” call to six command wrappers. `after_a_save` still refreshes the Rust cache and may discover that an external writer already replaced the committed revision; it already treats that as a successful commit with no reliably moved identity (`src-tauri/src/commands.rs:1667-1715`). In that case the ledger still records only the revision this app actually committed, while the differing post-save observation is queued as external. A committed write is never relabelled a failure.

`conflict_after_the_lock` does the opposite: it records no app write, refreshes the backend cache, and publishes/coalesces that external observation under the same sequence allocator. Its current guarantee is that `disk_text`, `disk_revision`, projection, and reapply evidence come from one hash-paired snapshot (`src-tauri/src/commands.rs:1573-1602`, `src-tauri/src/commands.rs:1608-1632`). A later native hint with the same document and disk revision is a duplicate of that already observed external state, not a self-write, and is coalesced without producing a second conflict. Preserve the refresh: it is the cache-coherency half of the save conflict, not watcher UI adoption.

Backup writes do not widen the predicate. The backup root is `<config root>/.espansoconfig-backups`, a sibling of both watched directories, and discovery itself cannot see it (`crates/espansoconfig-core/src/persist/backup.rs:45-62`, `crates/espansoconfig-core/src/persist/backup.rs:881-914`). Watch exactly `config/` and `match/`, not the configuration root recursively, so batch creation, entry copy, marker writes, and rotation never enter the watch stream. If implementation instead watches the root and filters afterwards, it has changed the watch scope and must prove every backup temporary, marker, entry, and rotation event is excluded; there is no reason to accept that larger proof burden.

The truthful user/developer sentence is: **“This application ignores a filesystem hint when the bytes now on disk hash to the latest revision it recorded after committing that file; this proves the text is identical, not who wrote it.”** An external process rewriting identical bytes is indistinguishable by this predicate, and ignoring it is acceptable because the file text—the source of truth—did not change (`crates/espansoconfig-core/src/lib.rs:8-12`). Do not claim that the event “was ours,” that no external write occurred, or that metadata stayed unchanged. Hash equality proves byte identity subject to the hash's collision limit; the existing conflict contract states that limitation explicitly (`src/lib/browser/saveOutcome.ts:726-740`).

## Q3 — The wire

**Ruling: use both a Tauri push and a poll command—the push is an expendable wake-up carrying `{ workspaceEpoch, newestSequence }`, while `drain_external_changes(afterSequence)` returns the authoritative typed, ordered, coalesced observations.**

A push-only full snapshot is unsafe because the listener can attach after a change, the webview can be suspended, and Tauri delivery order is not an application-level reconciliation order. A timer-only poll makes every idle window wake forever and adds latency despite a native notification already existing. The combined protocol makes both limitations explicit: emit `workspace://reconciliation-ready` after enqueue, and let the frontend immediately drain; also drain after listener registration, after `open()` completes, and on foreground/resume. The event payload is only:

```text
ReconciliationWake { workspace_epoch: u64, newest_sequence: u64 }
```

The command answer is a `CommandResult<ReconciliationBatch>` in the existing TypeScript convention, where `ReconciliationBatch` carries the current epoch, the highest sequence returned, and observations ordered by sequence. The Rust command surface currently returns `Result<T, CommandError>`, while the TypeScript wrapper converts invoke success/failure into `CommandResult<T>` (`src/lib/ipc/commands.ts:230-245`); preserve that split. The event is not a `CommandResult` because it reports no requested operation. An epoch mismatch makes the whole wake or drained batch stale and installs nothing.

Use a discriminated observation value, not rendered prose and not raw `notify::EventKind`:

```text
ExternalObservation =
  Changed { sequence, document, previous_revision, disk_revision,
            disk_text, disk, findings, correspondences }
| Added   { sequence, document_summary, disk?, findings }
| Removed { sequence, document, previous_revision }
| Unreadable { sequence, document_or_relative_path, reason }
```

`correspondences` is snapshot-bound evidence derived in the core from the cached pre-change `SourceDocument` and the stabilized post-change one. It must provide the editor's flexible correspondence and the exact-item correspondence required by delete/move/duplicate, plus exact placement correspondence; never send `ReapplyAnchor` itself, which is intentionally digested, captured before refresh, and forbidden from crossing IPC (`crates/espansoconfig-core/src/reconcile.rs:95-130`, `crates/espansoconfig-core/src/reconcile.rs:179-200`). Both sides of a move must come from one fresh snapshot, as the core's current `reconcile` contract requires (`crates/espansoconfig-core/src/reconcile.rs:450-469`, `crates/espansoconfig-core/src/reconcile.rs:533-567`). A document not loaded in the backend needs no correspondence table; no open frontend surface can legitimately hold a `MatchId` from an unprojected file.

The queue guarantees only: sequences increase within one workspace epoch; observations returned in a batch are sequence-ordered; repeated hints that stabilize to the same document/revision coalesce; and for each document the frontend acts only on the highest sequence it has accepted. It must not infer filesystem chronology from hashes, assume one native event per write, assume two documents are globally ordered on disk, or assume a wake corresponds one-to-one with a queued value. A `Removed` followed by `Added` at the same path is two observations even if the new bytes hash like old bytes, because file membership changed; an ordinary content rewrite with equal bytes is no content observation.

Every enum/code that can produce a visible sentence—unreadable reason, removal state, conflict origin, watcher failure/degraded mode—crosses as a code plus operands. It gets English and Spanish entries, a typed `describe*`/reactive `t*` accessor, and registration in the Rust dictionary contract. That contract checks both dictionaries in both directions and derives `code.<enum>.<variant>` (`src-tauri/src/dictionary_contract.rs:1-30`), while also admitting that it proves key existence and parity, not meaning (`src-tauri/src/dictionary_contract.rs:77-92`). Components call accessors rather than building keys (`CLAUDE.md:528-534`). The typed frontend event/listener wrapper must be injectable just like `BrowserCommands`, whose current interface exists so tests can drive state without Tauri (`src/lib/browser/workspace.svelte.ts:120-148`, `src/lib/browser/workspace.svelte.ts:284-298`).

## Q4 — The no-draft path

**Ruling: “no dirty draft” means the narrower conservative predicate “no open write surface can target this document”; only then call a distinct guarded automatic-reload transition, never `adoptDiskVersion`.**

R36 overrules the plan's wording at the point of implementation. `documentHasUnsavedDraft` measures any open match editor, dirty or pristine; it cannot see the session-local derived `isDirty`, excludes the raw editor, and cannot prove its input list is complete (`src/lib/browser/matchDuplication.ts:300-339`). The refusal copy already says an editor is open and that this application cannot tell whether it was edited (`CLAUDE.md:312-319`). Phase 2d must use the same truth. A pristine match editor, raw editor, creator, deleter, mover, duplicator, or restore pane therefore prevents automatic reload when it can target the changed file. Over-refusal costs a close/reopen; under-refusal can discard a draft or leave an operation holding identities from vanished bytes.

The coordinator needs a new exhaustive `OpenWriteSurface` registry for watcher policy. The current restore-oriented producer is useful evidence but not sufficient: it lists raw editor, match editor, deleter, mover, duplicator, and restore (`src/lib/components/DetailPane.svelte:473-494`), expressly omits the creator because the pane cannot see its chosen target, and admits that no type proves the list complete (`src/lib/components/DetailPane.svelte:453-469`). For watcher purposes represent the creator as `{ kind: 'matchCreator', target: 'unknown' }`; while it is open, conservatively treat every changed match document as potentially targeted. Do not call that “dirty.” The current `busy` value proves the pane knows whether any of its seven write surfaces is open (`src/lib/components/DetailPane.svelte:649-665`), so the registry should be coordinator-owned rather than reconstructed by watcher callbacks.

Automatic reload is not adoption. `adoptDiskVersion` is an authorization-and-spend operation for a conflict a particular `BrowserState` remembered, with origin, document, generation, and one-shot guards (`src/lib/browser/workspace.svelte.ts:2045-2135`). A clean external change has no conflict and no human confirmation to spend. Add `applyExternalObservation(observation)` as a guarded coordinator transition, or drive the already shipped `rereadDocument(document)` from it. The latter already captures open-workspace, per-document reread, and projection generations before awaiting; drops stale answers; calls `installView`; repairs selection; and refreshes the raw viewer (`src/lib/browser/workspace.svelte.ts:2351-2403`). Do not bypass it by assigning `views` directly.

The two counters remain separate. `installView` invalidates only that document's projection generation and forgets text paired with the replaced projection (`src/lib/browser/workspace.svelte.ts:1786-1804`); every selection replacement bumps the global intent counter in the same synchronous block (`src/lib/browser/workspace.svelte.ts:1637-1671`). `repairAfter` re-resolves a selection in the new projection, keeps it only when the correspondence says same match, and otherwise clears it with the external-change notice (`src/lib/browser/workspace.svelte.ts:3540-3556`). An automatic reload must use all three functions in that order; collapsing the counters previously left a stale `MatchId` selected with every test green (`CLAUDE.md:336-344`).

The brief's description of the third pane also needs correction. The raw **viewer** is read-only and may auto-refresh: `installView` invalidates its paired text and `rereadDocument` reads it again. The restore pane is not a read-only mode for reconciliation purposes; it is the seventh write surface, keeps a candidate and can replace a whole file (`PROGRESS.md:103-106`; `src/lib/components/DetailPane.svelte:931-958`). It therefore enters conflict, preserving its candidate, rather than auto-reloading underneath it. A raw **editor** likewise conflicts. Read-only match detail and raw view repair normally. Added/removed documents update sidebar/list state under the same selection counters; a removed selected document clears selection and raw text, never hands its `DocumentId` to a new path.

## Q5 — The draft path

**Ruling: watcher-origin conflict is a distinct discriminant inside the one shared conflict model, and only the newest accepted observation for a document may be active; the existing adoption door and choice-list producer remain unique.**

Do not forge a `SaveResult::Conflict`. That value says a locked save read refused a write, carries `expected` and `found`, and supports the message “this attempt wrote nothing” (`src-tauri/src/save.rs:200-230`; `src/lib/browser/saveOutcome.ts:697-716`). A watcher conflict has no attempted save, no locked `found`, and no save-origin “nothing was written” fact. Generalize the model to a source union such as `ConflictSource = { kind: 'save', value: ConflictResult } | { kind: 'externalChange', value: ExternalObservationChanged }`, with origin-specific messages and one common disk snapshot, retained draft, reapply evidence, reload state, and capabilities. The watcher sentence is narrowly: “The file changed on disk while this write surface was open; this application has not overwritten either version.” It must not say an attempted save wrote nothing because there was no attempt.

The one-door rule survives by generalizing the registry key, not by adding `adoptExternalVersion`. `rememberTheConflict` currently records the exact wire object and the projection generation at arrival, and installs nothing (`src/lib/browser/workspace.svelte.ts:1552-1566`, `src/lib/browser/workspace.svelte.ts:1604-1620`). Key it by either origin object's identity and keep `adoptDiskVersion(conflict, confirmation)` as the sole confirmed install. Its existing `installed | alreadyThere | refused` outcomes stay exact: already holding the requested revision is success, while a replaced projection refuses an older snapshot (`src/lib/browser/workspace.svelte.ts:2098-2127`). Likewise `conflictChoicesFor` remains the only choice-list producer; it already centralizes copy, reapply, and the two-step reload ordering (`src/lib/browser/saveOutcome.ts:475-534`). Origin changes messages and evidence provenance, not who is allowed to produce controls.

The surface transition that receives an external observation snapshots its current immutable draft/operation and builds the same `ConflictModel<T>` family its save-result transition builds. The correspondence table must be bound to that observation's `disk_revision`; if it is absent, ambiguous, or from an older observation, *Keep my draft* resolves to manual resolution and sends no command. This preserves the core rule that a target index is never a tie-break and that destructive operations require exact-item evidence (`crates/espansoconfig-core/src/reconcile.rs:147-176`, `crates/espansoconfig-core/src/reconcile.rs:547-561`). The file's disk text and projection remain paired exactly as they are in a save conflict; a second `document_text` call is forbidden because it could show a different observation (`src/lib/browser/saveOutcome.ts:742-753`).

Two conflicts do not coexist on one surface. Once a watcher conflict is installed, ordinary submit controls are disabled until the person chooses a resolution, so a later save-origin conflict cannot normally be initiated. The race is a save already in flight when a watcher observation arrives. Resolve it through the backend sequence, never promise event-vs-promise arrival order: queue the watcher observation, settle the save result, then drain. A save-origin conflict registered by `conflict_after_the_lock` wins over a native duplicate at the same document/revision because it has the locked refusal fact and operation-specific reapply evidence; the duplicate is coalesced. A strictly later accepted observation with a different revision supersedes the older conflict's disk side and invalidates its reapply evidence. It keeps the retained draft, offers compare/copy/reload and eligible recovery, but requires manual resolution unless fresh correspondence was computed from the original base. Hashes have no temporal order, so “later” here means the coordinator's observation sequence, not digest comparison (`src/lib/browser/workspace.svelte.ts:2119-2125`).

If an in-flight save committed, that committed outcome remains true and its own frontend invalidation/adoption completes first; the ledger suppresses its matching watcher hints, and only a differing later observation becomes an external conflict or clean reload. If a write may have committed but returned an error, do not auto-reload it away: `run_one_save` currently evicts the cache on `may_have_written` precisely because a stale projection is worse than a reparse (`src-tauri/src/commands.rs:987-1042`). The watcher may later establish a stable disk observation, but it cannot retroactively decide whether that uncertain send wrote.

## Q6 — The offer

**Ruling: all five plan offers ship in 2d by reusing the 2c machinery, but only Keep/Reload/Copy are controls in the primary list—Compare is the always-visible evidence and Save-as-new is a staged manual-resolution recovery, not an exact duplicate.**

1. **Keep my draft / request.** Use the 2c-4b reapply transitions on the watcher observation's snapshot-bound correspondence. Reapply means install the observed disk projection through the confirmed one-door protocol, rebuild field intent or the operation over it, clear stale acknowledgement, and return to the ordinary submit path; it does not immediately write. The existing model explicitly distinguishes `reapplied` from `alreadySatisfied` and says the next save may refuse or conflict again (`src/lib/browser/reapply.ts:185-227`). Raw whole-document text remains unsupported because reapplying it would be a stale whole-file overwrite or an automatic text merge, both forbidden (`src/lib/browser/saveOutcome.ts:343-373`; `src-tauri/src/commands.rs:1530-1540`). It must never say “merged,” “saved,” “all changes applied,” or “the same snippet was found” when correspondence was provisional or refused.

2. **Reload disk version.** With an open surface, retain the shipped two-step warning and confirmation, then call `adoptDiskVersion`; raw editor reseeds its draft, five match surfaces close, and restore keeps its candidate while retargeting its base (`src/lib/browser/saveOutcome.ts:296-328`). `alreadyThere` is success and `refused` closes nothing. Without a write surface, automatic reload is the separate Q4 transition and has no confirmation. The control must never say the disk version is newer—hashes are unordered—or say a match surface's text is replaced when that surface actually closes.

3. **Compare.** Do not add a diff engine or a writable merge view in v1. The shipped conflict model already carries the whole exact disk text specifically as the comparison side (`src/lib/browser/saveOutcome.ts:718-755`), and the raw panel draws it through `SourceText` rather than a textarea (`src/lib/components/RawEditor.svelte:591-609`). Authored-text surfaces show labelled retained fields; operation surfaces show an operation summary; if no corresponding match can be identified, show the whole disk document and say so rather than fabricating empty disk fields. “Compare” is therefore the panel itself and may be cut as a dedicated button, but the comparison evidence may not be cut. It must never call a visual juxtaposition a merge, semantic diff, or proof that only the shown fields changed.

4. **Copy draft to clipboard.** Reuse `copyReferenceText`. The raw editor copies its retained whole text; match editor and creator copy the localized labelled reference assembled from the same retained fields the panel shows, explicitly not YAML (`src/lib/browser/saveOutcome.ts:1181-1251`). Deleter, mover, duplicator, and restore hold operation/candidate values for which the existing capabilities correctly withhold this particular draft-copy control. The asynchronous clipboard API is the only known route that preserves a real carriage return; if it fails, the textarea fallback must refuse such text (`src/lib/components/clipboard.ts:178-213`). It must never report success after normalization, advise hand-copying a `SourceText` rendering that names rather than contains `\r`, or call the labelled reference paste-ready YAML.

5. **Save draft as a new snippet.** The brief's framing is not what shipped. The existing recovery is offered only after *Keep my draft* reaches `manualResolution`, and only for match-editor or creator authored fields; operation choices and whole-document text have no honest snippet-shaped draft (`src/lib/browser/recovery.ts:280-313`, `src/lib/browser/recovery.ts:510-534`). Keep that staged design rather than adding a seventh primary `ConflictChoice`. It creates a new snippet at the end of an explicitly eligible destination and uses the ordinary `BrowserState.createMatch` path. What it truthfully preserves is the supported final logical value of trigger, replacement, label, word, left-word, and right-word where each can be carried; it may require the two mandatory values to be entered. It does not preserve comments, unknown keys, key order, scalar spelling, tags, anchors, sixteen other scalars, or four collections—the shared recovery renderer says exactly that (`src/lib/components/RecoveryPanel.svelte:80-115`; `src/lib/browser/recovery.ts:674-690`). It must be labelled “Create a new snippet from supported fields,” never “Duplicate,” “Save an exact copy,” “move my draft,” or “preserve the original snippet.” D2r and R25 remain untouched: this is a creation, while any later repositioning is its own same-sequence move (`src/lib/browser/recovery.ts:787-803`).

All origin-specific messages and all five offer/refusal sentences go through English and Spanish accessors. Tests must inspect the semantic claims, not only key parity, because the dictionary contract expressly cannot tell whether a sentence is true (`src-tauri/src/dictionary_contract.rs:77-90`), and this repository identifies guarantee prose as its worst recurring defect class (`CLAUDE.md:376-378`).

## Q7 — The split

**Ruling: cut 2d into eight dependency-ordered steps; the phase inherits model, mounted, and window evidence as a safety requirement even though the literal “every sub-phase” rule was scoped to 2c, and only the native-adapter step owns a real-filesystem watcher integration test.**

1. **2d-1 — core observation engine, no caller.** Add `notify`, the two watched roots, per-path debounce, consecutive-read stability, exact hashing, projection/validation, typed changed/added/removed/unreadable observations, rescan, and snapshot-bound correspondence tables. Core tests use injected hints/clock/reader and synthetic temp trees; cover bursts, atomic rename shapes, partial writes, read-error recovery, non-UTF-8, deletion/recreation, parse failure, semantic findings, recursive nested match files, disabled files, and packages. This step must not touch Tauri, commands, Svelte, i18n, or saves. The architecture remains testable and Tauri-free (`crates/espansoconfig-core/src/lib.rs:1-12`, `crates/espansoconfig-core/src/lib.rs:127-143`).

2. **2d-2 — native lifecycle and real-filesystem adapter.** Put one core watcher handle behind the open `WorkspaceSession`, with workspace epochs, cancellation/join on successful replacement, drop on shutdown, native-error polling fallback, and a temp-directory integration test using real creates, atomic renames, edits, and removals under both roots. This is the only step whose principal integration test belongs in `src-tauri`; a `notify` callback plus workspace replacement is not a pure core question. It must not emit to a window or change conflict UI yet.

3. **2d-3 — save composition and suppression ledger.** Extend `run_one_save`, `after_a_save`, and `conflict_after_the_lock` with the one per-document app-write revision record, external-observation sequence, duplicate coalescing, and uncertain-write handling. Prove all six writers record only committed revisions, `committed: false` records none, conflict refresh is external rather than self, post-commit external replacement is not suppressed, and backup creation/rotation generates no watched observation. Do not add a writer, a force flag, or any route around `save_document`, which is the only entry point allowed to write a user file (`CLAUDE.md:462-474`).

4. **2d-4 — queue, event wake, drain command, and wire contracts.** Add the typed queue, `workspace://reconciliation-ready`, `drain_external_changes`, TypeScript types/wrapper, command registration/dispatch tests, sequence/epoch/coalescing tests, and EN/ES code namespaces/accessors for every visible failure. The event remains a hint; the command answer is authoritative. This step must not draw anything or decide whether a surface is open. Update the registered-command count rather than continuing to claim fifteen; the present application registers fifteen workspace commands and one menu command (`src-tauri/src/main.rs:73-127`; `src-tauri/src/wire_contract.rs:1425-1492`).

5. **2d-5 — browser coordinator and pure surface transitions.** Add listener/drain orchestration, per-document accepted sequence, the exhaustive open-surface registry including wildcard creator, guarded automatic reload, watcher-origin conflict source, origin-specific messages, same-revision save/watcher coalescing, and newest-observation arbitration. Generalize `rememberTheConflict`/`adoptDiskVersion` without adding a second door, and keep `conflictChoicesFor` the only producer. ## Q8 — The sharpest failure mode

**Ruling: the sharpest green-suite failure is an incomplete or stale open-write-surface registry classifying a live surface as clean, so an external hint automatically replaces its projection and silently strands or discards the retained draft/request.**

This is sharper than duplicate notification cosmetics and more plausible than a hash collision. R36 means dirty state cannot rescue the decision (`CLAUDE.md:312-319`); the current only producer of open surfaces expressly cannot prove completeness and omits the creator's chosen target (`src/lib/components/DetailPane.svelte:453-469`); and automatic installation invalidates a document's projection generation and can repair or clear selection (`src/lib/browser/workspace.svelte.ts:1786-1804`, `src/lib/browser/workspace.svelte.ts:3540-3556`). Every suite can therefore be green while the one real callback path erases the only in-memory copy of a draft.
