## 2. Finding 1 (SHOULD-FIX, Medium) — the two-witness sentence attributed driving to a test that issues no drain

`reconciliationCoordinator.ts`, the sentence 2d-5-3-K wrote as *"the claim the paragraph actually
needs"*: *"**The two tests that come nearest drive that overlap somewhere other than Rust, and
nothing wider is claimed here.**"*

**Re-derived against the passage, not accepted from the review.** *"That overlap"* is fixed by the
sentence before it: *"a further successful open may have installed another lifecycle and emptied the
queue by then"* — an open landing while a drain is in flight. The sentence predicates *driving that
overlap* of both tests. Two lines later the same passage says of the first,
`workspace.test.ts`'s *"lets the newer open win, however late the older one answers"*, that it
*"overlaps two **opens** with each other and issues no drain at all"*. A test with no drain drives an
open-during-drain overlap **nowhere** — not *"somewhere other than Rust"*. The wording K replaced
(`git show aa025fa`, the removed lines) had called that test a near miss and predicated nothing of
it; the rewrite did. **K's own record compounds it**: `2d-5-3-K-notes.md` §2 says the sentence *"is
pinned by the two derivations immediately under it"*, and one of those derivations is the one that
contradicts it.

**Fixed in source**, and the replacement is a claim about the two tests the paragraph *cites* rather
than about which tests come *nearest*:

> *"Of the two tests cited here, one drives that overlap and does so against an injected host, and
> the other does not drive it at all; nothing wider is claimed here."*

with *"so it is the one that does not"* added to the `workspace.test.ts` sentence so the pairing is
explicit. **What the new sentence asserts, and what pins each part.** That the paragraph cites
exactly two tests is pinned by the paragraph. That the coordinator test drives the overlap against
an injected host is K's §5 bullet, re-derived again this round by the reviewer: *"installs nothing
from a drain an open overtook"* does `control.generation += 1; coordinator.workspaceOpened();` with
a drain outstanding on the injected host. That the host test does not drive it at all is the absence
of any drain in its body — the reviewer read lines 1229–1253 and found no `start()` and no drain, and
this round's own sweep found every `state.start()` in that file thousands of lines below it. **The
unpinnable half is gone with the sentence**: K's §7 item 1 recorded that *"which two tests come
nearest"* is a claim nothing in the repository can check, and the replacement makes no claim about
nearness. Both items now carry a `Correction, 2d-5-3-L` block in the K notes, and the archived K
record in `next-action-history.md` carries the correction in its preamble.

**It is not a false absence written to replace a false coverage claim** (2d-5-3-E's shape), for the
same reason K's §2 gave: the universal is asserted in neither direction, and the sentence that
replaces the over-attribution claims less than the one it replaces, not more.

## 5. A host finding: the stale build cache of a relocated checkout, in two places

**The inherited-tree gate run failed `cargo test` and `cargo clippy` with exit 101 before a single
test ran**, while the four frontend and format gates in the same sequential script passed. The error
was tauri's build script failing to read a permissions file under
`/Users/ccarpio/Developer/espansoConfig/target/…` — the repository's **previous** location, which
`ls` confirmed no longer exists. Cargo reuses a build script's recorded output until one of its
`rerun-if-changed` inputs changes, and moving a checkout changes none of them, so the absolute path
tauri's build script had written into its output at the old location was replayed at the new one.
**`cargo clean -p tauri`** removed that crate's artefacts (1912 files) and the Rust gates were re-run
alone — clippy now passed, and `cargo test` failed again, **in a second place**: all 17 tests of
`corpus_integrity` panicked reading fixtures under the old path, because
`tests/common/mod.rs` fixes the corpus root with `env!("CARGO_MANIFEST_DIR")` at compile time and
cargo had reused the test binary compiled at the old location. Every artefact under `target/` was
built there, so the honest remedy was a **full `cargo clean`** — 965,588 files and 103.4 GiB of
accumulated output — and one rebuild from scratch (247 crates compiled; `target/` is 2.6 GiB after
it). The complete run that followed is the one §6 records.

**Not a source finding, and not a flake.** It is deterministic, it names a path, and the path does not
exist. **What a later session should not have to rediscover**: a build-script error or a test panic
whose message names a directory that is not this checkout is the cache, not the source; check the
path with `ls`, then `cargo clean` — the whole directory, because a per-crate clean found the second
instance only by running into it. It joins the flaky `watch_check` section as a host fact but is not
added to it: that section's three consequences are about a different failure with a different cure.

**One consequence for this round's evidence.** The inherited-tree Rust reading was attempted twice and
completed neither time, and the frontend figures of that tree were taken by a script whose Rust half
had failed ahead of them. The Rust tree is byte-identical between the inherited and the committed
trees except for the instrument's `main.rs` (`git diff --stat aa025fa -- crates src-tauri Cargo.toml
Cargo.lock` names only it), so the committed tree's Rust figure is a figure about the same Rust
source — but it is **one** complete reading, not this tail's customary two, and §6 says so rather
than counting the failed attempts.
